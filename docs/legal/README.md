# Legal Index

Dated FOSS-licensing analyses produced by `legal-licensing-researcher`. Each entry answers a single concrete licensing question with a mandatory **quad-jurisdictional profile** — 🇷🇺 RU / 🇺🇸 US / 🇪🇺 EU / 🇷🇸 RS — and line-level citations into the source (`LICENSE`, `pyproject.toml`, `package.json`, `license_texts/`, per-file headers) plus canonical external references (SPDX, FSF, OSI, CJEU, ВКС РФ, ЗАСП). Sorted by date, newest first.

> **Disclaimer.** Every document in this index is **informational FOSS-licensing analysis** prepared by an automated agent based on publicly available license texts and project source. **It is not legal advice.** Binding decisions — especially on distribution, commercialization, redistribution to third parties, enforcement, or litigation — require review by a qualified lawyer admitted in the relevant jurisdiction. The per-document disclaimer inside each file is authoritative for that file.

## How to read a document

Every legal finding under this directory follows the same structure (see the agent spec at [.claude/agents/legal-licensing-researcher.md](../../.claude/agents/legal-licensing-researcher.md)):

1. **Summary** — 2–3 paragraph plain answer, with RU / US / EU / RS divergences listed.
2. **Facts Established in the Repository** — `[path:line]`-cited facts from `LICENSE`, manifests, and source.
3. **Licenses Involved** — SPDX identifier → canonical source mapping.
4. **Jurisdictional Analysis** — four sections, each in the fixed order:
   - **(a) What holds** — settled statute / case law / authoritative-body position.
   - **(b) What is unsettled** — gaps, absent case law, `TODO(verify)` markers.
   - **(c) Practical obligation for ERPNext** — concrete action items.
5. **License Compatibility Matrix** — when applicable.
6. **References** — repo paths plus canonical external URLs.
7. **Open Questions** — outstanding `TODO(verify)` items.
8. **Changelog** — version history of the document.

The four jurisdictional sections are backed by four skills living under [.claude/skills/](../../.claude/skills/): [legal-ru](../../.claude/skills/legal-ru/SKILL.md), [legal-us](../../.claude/skills/legal-us/SKILL.md), [legal-eu](../../.claude/skills/legal-eu/SKILL.md), [legal-rs](../../.claude/skills/legal-rs/SKILL.md).

## Adding or updating a finding

Do not edit this file by hand. The `legal-licensing-researcher` agent maintains it automatically after every `Created: ...` or `Updated: ...` write to `docs/legal/*.md`. To produce a new finding:

- Interactive: invoke `/research-legal <question>` (English) or `/ru:research-legal <вопрос>` (Russian).
- Programmatic: spawn the `legal-licensing-researcher` subagent with the research question and any starting files.

The agent enforces the quad-jurisdictional structure, the disclaimer block, reuse of existing documents covering ≥70% of the same scope (extending in place rather than duplicating), and appends an index row here.
