# Цель

Создать или расширить архитектурную документацию в `docs/` под указанную область.

**Область:** `$ARGUMENTS`

# Как выполнять

1. Если `$ARGUMENTS` пуст — **не** вызывай агента сразу. Сначала спроси у пользователя, с какой области начать. Предложи 3–4 приоритизированных варианта:
   - `architecture` — базовые документы (controllers, hooks, lifecycle). Рекомендую первым.
   - `accounts` — поток учёта (GL, налоги, платежи).
   - `stock` — поток склада (SL-записи, batch/serial).
   - `all` — пройти все области последовательно.

2. Как только область определена, делегируй работу сабагенту `architecture-researcher` через Agent tool с `subagent_type: "architecture-researcher"`.

3. В промпте агенту обязательно укажи:
   - Точную область.
   - Требование показать план до создания более 3 файлов и дождаться согласования пользователя.
   - Требование в конце обновить `CLAUDE.md` указателями на `docs/`.
   - Любые дополнительные ограничения, упомянутые пользователем при вызове.
   - Язык документации: **русский**.

4. Получив ответ агента, передай пользователю его финальный отчёт дословно (созданные файлы, обновлённые файлы, рекомендуемые следующие области). Не добавляй своих комментариев.

# Ограничения этой команды

- Не пиши код или документацию напрямую в рамках этой команды — это работа агента.
- Не обходи и не меняй шаги согласования, заложенные в агента.
- Не вызывай других агентов для этой работы.
